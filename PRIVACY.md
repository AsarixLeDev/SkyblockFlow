# Privacy

SkyblockFlow has no analytics or crash-upload service. Most features read the game state and keep their settings and history in `config/skyblockflow/` on your computer. Optional network features are described below.

## Local data

Settings, job/pet/leaderboard history, waypoint locations and map tiles, energy plans and bounded machine block/menu observations, blocked-player preferences and imported media remain local unless you explicitly export or share them. Exports can contain locations and names: review a bundle before sending it to someone. Discord credentials are excluded from profile exports. Energy observations exclude the player inventory, are kept locally with each saved machine, and are removed when that saved block is deleted. Menu observation and block highlights can be disabled in the planner’s Selector settings.

## Shared edits

Sharing starts off. The disclosure must be accepted for the selected relay before it connects. The default relay is `https://flow-edit-relay-production.up.railway.app`, operated for this project by its author, **asarix on Discord**. A custom relay has its own operator and policies; enable sharing only if you trust them.

The relay receives your Minecraft name/UUID, an opaque connection context and blocking preferences. Minecraft identity is checked through Mojang: the game access token is sent to Mojang's session service, never to the relay. A fresh proof is generated by the client. Relay authorization stays in memory.

Sending an edit uploads its selected MP3, optional PNG, presentation settings and hit timeline. Terrain sharing additionally sends nearby blocks, light, positions and subject appearance/equipment data. Both players must accept their participation. HTTPS protects transport, but the relay operator can inspect content while handling it; it is not end-to-end encrypted.

The current relay removes media on completion, cancellation, decline or expiry. Unused uploads expire after ten minutes; pending invitations expire after two minutes; accepted preparations after three minutes. Scheduled playback has a bounded deadline. Expiry cleanup runs every thirty seconds, and a restart clears orphaned media. Finished/cancelled invitations retain a minimal status record for up to thirty seconds so both clients can observe the result. Connection and blocking records are memory-only and expire after two minutes of inactivity. Completed-share cooldowns last five minutes; rate-limit keys expire after two minutes without activity. These are not a permanent sharing history. Hosting-provider operational logs may have separate retention; application access logging is disabled and the relay does not log media or authentication tokens.

Received media is temporary by default and is removed after playback or cancellation. Crash leftovers are removed at the next launch. **Keep downloaded songs** optionally keeps verified audio on the local computer, up to 512 MB. **Clear saved songs**, or turning that setting off, deletes these copies. Imported originals are never deleted by that control. Images and terrain are not retained for reuse.

Press Esc to stop playback, use `/stopedit` to cancel and clear uploads, block a sender, block all invitations or turn sharing off. A failed share does not consume the five-minute success cooldown. The short retry limit still applies.

## Community names

This feature is off by default. Its scrollable explanation is under **Features → Community names**. Consent stays in a separate local file and is excluded from shared profiles. While enabled, launch loads the verified local appearance cache and checks the public appearance document. Account verification and presence start only after joining a world, independently of edit sharing. Disabling the feature stops both.

The same publisher relay receives your Minecraft name and UUID to verify identity through Mojang. Your game access token goes only to Mojang. The relay also sees ordinary connection information, including your IP address. Application rate limits use a per-process salted hash of the IP/network in memory, expiring after two minutes without activity; hosting-provider logs have their own retention.

Opting in makes your UUID and participating presence available to other authenticated participants, across servers. No chat, server address or location is sent. Heartbeats run every thirty seconds. Turning the feature off removes presence; interrupted connections expire within two minutes of the last heartbeat, plus the cleanup interval. Tokens stay in memory. Appearance and edit-sharing permissions are separate.

A public signed document contains the publisher's default style and any UUID-specific overrides. Those overrides are intentionally public and remain until the publisher removes them. The mod caches this document locally and refreshes it every five minutes. It verifies the publisher's Ed25519 signature and accepts only the bundled fonts and validated colors, including gradients. Saturated reds and near-black colors are rejected; orange and gray are allowed. There is no public style-editing endpoint. Only participating clients display the styling; unidentified server chat and nicknames are left unchanged.

## Discord

Discord connection is unavailable in this beta pending public-access verification. When available, approval happens on Discord's own page using PKCE and a temporary loopback callback. The publisher application ID is `1572690819566276729`. Account and voice-call data are read directly through Discord and its local desktop RPC connection.

The overlay reads profile and voice-call information after approval. Microphone/deafen controls require a separate opt-in. It does not record call audio. Remember this device is off by default. If enabled, tokens are stored in a separate OS-account-restricted file, not encrypted. Programs running as the same computer account can still access the file or process memory.

Disconnect revokes authorization. Failed revocations are kept only to retry removal; a crash cannot guarantee immediate revocation. You can always remove access in Discord Settings → Authorized Apps. Revoking the grant also disconnects other installations authorized through this application. See [Discord release requirements](DISCORD-RELEASE.md) for public-access and platform verification status.

## Other connections

| Optional feature | Destination and purpose |
| --- | --- |
| Rocket League | Liquipedia API for match data, and its image host for team logos. Requests disclose the normal connection IP and user agent. |
| Discord portraits | Discord CDN, using avatar identifiers supplied by Discord. |
| Staged edit avatars | Official Minecraft profile/session services and signed skin textures. |
| Spotify | A bundled read-only desktop helper reads local Spotify metadata; cover art may come from Spotify's image hosts. No Spotify login is requested. |
| Discord unread badge | Reads the desktop window's unread count where the OS/client exposes it. |

The desktop helper is shipped as readable Python/PowerShell source and runs only when a related overlay is enabled. It does not download executable code. Desktop integrations depend on OS support.
